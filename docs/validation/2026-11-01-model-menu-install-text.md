# 终端模型下拉看不清、增装进度文案修复

[验收记录索引](README.md)

## 问题

11-01 决赛前全量实测里的两个小问题：

- **F07**：终端里展开“会话模型”的下拉，白底上的模型名是很浅的灰绿色，投影时几乎看不清。供应商表单里的同一个下拉没有这个问题。
- **同一个下拉的滚动条**（复查时发现，main 上就有）：模型多到出现滚动条、系统设成“始终显示滚动条”时，在滚动条上一按，列表就收起，拖不动。
- **F08**：给已停止的沙箱增装智能体时，进度写“准备智能体镜像，当前沙箱继续运行”，和沙箱实际停着的状态不符。

## 原因与改动

- **F07**：下拉 `.model-options` 只设了白色底，文字颜色继承外层。终端里外层的会话栏 `.conversation-controls`（`main.css` 第 460 行）把文字设成给深色背景用的 `#c9dcd1`，下拉就成了白底配浅字。改动：`frontend/src/main.css` 给 `.model-options` 指定 `color: var(--ink)`，和页面正文同色。供应商表单里原本继承的就是这个颜色，不受影响。
- **滚动条**：输入框失焦就收起列表。在滚动条上按下时，WebKit 把焦点移出输入框，列表随即收起。选项本来就在按下时取消默认动作；改动：`frontend/src/js/model-picker.js` 把这个处理放到整个列表上，滚动条和底部“还有 N 个”提示也不再移走焦点。
- **F08**：这句进度在镜像准备开始时显示，运行中和已停止的沙箱都会走到这里。镜像准备这一步不动容器和配置：运行中的到替换容器那一步才停（那一步另有“保存用量并更新容器，终端会话将结束”的提示），已停止的仍然停着。但运行中的沙箱在整个操作期间不能新开会话、不能发消息，“继续运行”容易被理解成还能照常用。改动：`internal/runtime/install.go` 改成“准备智能体镜像，这一步不会改动沙箱”，只说这一步做什么，不涉及能不能用。

## 实测

- **F07**：用 WKWebView（macOS 26.6.1，WebKit 21624.4.5.11.5，每次不留缓存）加载真实前端和模拟后端，用键盘在终端开一个 Codex 会话，再聚焦“会话模型”输入框，量第一项的文字色和下拉底色：

  | | 文字色 | 底色 | 对比度 |
  |---|---|---|---|
  | main（3d1bb4c） | `rgb(201, 220, 209)` | 白色 | 1.43:1 |
  | 本分支 | `rgb(37, 49, 59)` | 白色 | 13.28:1 |

  截图确认模型名清楚可读。正文文字一般要求对比度至少 4.5:1。
- **滚动条**：用复查人的 WKWebView 运行器（只在测试进程里设成“始终显示滚动条”，不改系统设置），终端会话里给 60 个模型，在列表滚动条上按住往下拖：见下方“滚动条实测”。
- **F08**：只改了文字，没有重新增装智能体（未缓存的组合要构建约 8 分钟，11-01 全量实测里两次分别是 480 和 448 秒）。`go test ./internal/runtime/` 通过；代码和测试不依赖这句文字，旧的审计报告和验收日志里保留着旧文字，不改。
- **滚动条实测**（用键盘在终端开 Codex 会话，再点会话模型输入框；滚动条宽 17 像素）：

  | | 按住滚动条往下拖 | 再点列表里的 model-07 |
  |---|---|---|
  | main | 列表立刻收起 | 列表已经没了 |
  | 本分支 | 列表还在，滚动到 286 像素处 | 输入框变成 model-07，列表收起 |

- 前端 `node --test` 28 项通过，`make check` 通过。

## 范围与限制

- F07 和滚动条只在 WKWebView 加模拟后端里看过，没在打包好的应用和投影仪上看。触控板默认的叠加式滚动条没有单独测。
- F08 的新文字没有在真实增装流程里看到过。
