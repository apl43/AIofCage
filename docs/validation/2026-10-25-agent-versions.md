# 智能体版本管理验证

设置中的“检查更新”只读取三款固定官方 npm 包的元数据，不安装包。可以选择检查成功的版本作为新沙箱默认，或恢复应用内置版本。默认版本不会修改既有沙箱；老数据缺少版本字段时使用其创建年代的固定版本，避免随应用更新漂移。

沙箱详情显示已生效版本、下次启动的目标版本与更新入口。用户选择更新后先准备候选镜像，成功后才结束会话并替换容器，项目和主目录保留；启动失败恢复原配置与原运行快照。停止中的沙箱在下次启动应用。版本参与镜像内容摘要，并限制为数字 SemVer 子集，不能进入任意命令或 Dockerfile 指令。

实测结果：

- 官方 npm 只读检查：Codex 0.164.0、Claude Code 2.1.310、DeepSeek Harness 0.2.1-rc.2；未更改用户默认版本。
- 一次性真实沙箱中 Codex 0.164.0 → 0.163.0 成功，`codex --version` 与配置一致，主目录标记文件保留。随后不存在的候选版本构建失败，原 0.163.0 容器仍运行。
- 初次旧版下载超过测试上限，暴露了 Docker/buildx 子进程持有管道导致取消不返回的问题。运行器现取消自身专属进程组，并限制管道等待；真实取消测试 2.64 秒完成，原 0.164.0 版本、运行状态和主目录完好。此前夹具及重试夹具的容器、网络和主目录卷均清理。
- 相关 runtime/service/sandbox/store 竞态测试、生产编译与 vet 通过。覆盖版本不漂移、默认与已有沙箱独立、未经检查版本拒绝、正式版/预发布顺序、防注入与子进程取消。
- Chrome 合成界面验证检查、设为默认与恢复内置入口；真实上游检查另用临时存储执行。未更新用户现有沙箱。

更新不是自动升级，也不自动改变模型协议或供应商配置。新版本若改变 CLI JSON 协议仍需兼容性验证；应用内置版本始终保留为可选恢复目标。回滚失败会明确报告，保留项目和主目录供重试。
