# 智能体镜像下载加速验证

[验收记录索引](README.md)

## 问题与改动

2026-10-25，macOS Apple Silicon 上首次启动 Codex 沙箱，构建停留在 `apt-get update` 下载约 8.7 MB 的 Debian arm64 软件索引。默认源连接缓慢，界面只显示“正在构建镜像”。

`internal/runtime/assets/agent/Dockerfile.tmpl` 在安装系统依赖前，将 Debian 主仓库、更新仓库和安全仓库切换到阿里云镜像。保留基础镜像固定摘要、Debian 签名校验、依赖清单和智能体版本。基础镜像尚未安装 CA 证书，因此沿用原仓库的 HTTP 传输；未设置 `trusted=yes`、允许未认证软件包或跳过证书校验。

本分支从 `8b3238c`（`fix/docker-context-initialization`）创建，包含该 Docker 连接修复；若其 PR 尚未合并，本分支 PR 依赖它。

## 实测

环境：专用 Colima profile `aiofcage`，Docker 29.5.2，目标 `linux/arm64`，Node 24.22.1 bookworm-slim，Codex 0.164.0。

- 在专用虚拟机中，读取同一 `Packages.xz` 文件的前 1 MiB，官方源 15 秒只收到约 151 KB；阿里云约 0.30 秒完成。此为当时网络下的抽样结果，不代表固定速度。
- 换源后的真实构建日志：9,293 KB 软件索引在约 8 秒内获取，下载和安装系统依赖整步耗时 33.6 秒。
- filesystem MCP 安装耗时 218.3 秒，Codex 安装耗时 63.2 秒；完整构建约 5 分 35 秒，Docker 构建记录状态为 `Completed`。
- 用户用生成的镜像启动 App 后反馈可以正常运行。这是用户操作反馈，本次提交验证未额外发送模型请求。

上述完整构建使用临时 Dockerfile，本提交将同一换源命令纳入正式模板。它只改变系统依赖下载来源；npm 仍使用官方源，安装阶段可能继续受网络速度影响。

## 适用范围

镜像内容标识随模板更新而变化，新版 App 首次使用会检查新的镜像标识。已完成的相同构建步骤可复用 Docker 缓存，已运行的沙箱不受源码提交影响。

本次未新增 npm 镜像、自动测速或下载源故障切换，也未新增界面构建进度、取消按钮。镜像源不可用时构建仍会失败，不降低校验要求。
