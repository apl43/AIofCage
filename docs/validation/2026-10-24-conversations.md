# 智能体会话与官方 CLI 验证

## 行为

智能体页面使用官方 CLI 的 JSON 管道，区分用户消息、回复、思考与工具活动。仅下方输入框可提交任务；不再向 TUI 注入 bracketed paste，因此正文不会出现 `^[200~`。Shell 单独保留 PTY，没有重复输入框。

新会话支持手动填写模型、读取当前供应商模型列表、选择默认/低/中/高思考强度。首条消息后锁定设置；需要更改时新建会话，原会话保留。上游决定模型与思考档位是否可用，应用不替用户切换供应商。工具按当前沙箱权限执行，项目仍可被修改；这不提供逐命令审批。

DeepSeek 采用官方 `deepseek-ai/deepseek-harness` 的 `dsh --profile headless --json`，不引入第三方 CLI。配置依据固定 npm `0.2.1-rc.2` 的 headless、agent-default-model、llm-pi-ai README、类型及实现。续聊使用原生 session ID。Codex `0.164.0`、Claude Code `2.1.309` 同样使用已安装版本的 help 核对参数。OpenAI 文档站在本轮抓取返回 403，未当作已读取证据。

## 已验证

- Python 5 项回归：长 final 保真、三 CLI 事件投影、Claude 流不重复、中文多行 stdin、参数不经 shell。
- 前端 reducer 2 项回归，所有模块语法检查；全包 Go 竞态回归及 `make check`。
- Chrome 中用明确的 `review-` 合成供应商及消息验证：创建 DeepSeek 会话、思考选择、消息分角色、代码块、统一新建菜单、Shell 仅有终端输入。观察到深色正文及按钮样式冲突，已修正并复查。此项证明界面行为，未用模拟响应冒充真实模型。
- 独立无网络容器，对三种真实官方 CLI 提供本地合成 SSE 上游：三者均退出 0、返回预期文本、提供原生会话 ID；捕获请求确认 Codex 的 `reasoning.effort=high`、Claude 的 `output_config.effort=high`、DSH 的启用思考与 16384 token 预算。模型字段与所选值一致。该测试验证协议适配，不证明供应商接受全部档位。
- 独立临时沙箱复用现有非敏感供应商配置及钥匙串引用：DeepSeek 两轮真实请求、暗号记忆、原生会话 ID 通过。Codex（七牛 xapi）、Claude Code（DeepSeek-CC）在 120 秒内未完成，主动停止；两项真实上游验收未通过，不将其归为成功或直接断言根因。新增显式启用的 `AIOFCAGE_CONVERSATION_E2E=1` 回归入口，方便复测。
- 所有测试沙箱、项目和 CLI 测试容器已清理。未启停、替换或修改用户已有沙箱。

## 实现复查

使用生效中的供应商快照，正文和附件不写入审计。前端文本节点渲染，禁止 HTML 注入；显示与消息数量有上限。每轮独立进程标记，停止、关闭、输出异常会清理容器内子进程；退出并行关闭会话。附件在当前会话期间保留、关闭时删除。已有运行容器缺少新组件时明确要求停止/启动，不热替换任务。

结构化消息目前随应用会话保留，重启应用后不恢复 UI 消息；原生 CLI 历史留在沙箱 home。尚未完成新版三种供应商的真实识图全链路验证。
