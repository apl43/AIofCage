# 启动完成后不再把人带走

[验收记录索引](README.md)

## 问题

11-01 决赛前全量实测的问题 F01（报告评为 P0）：在沙箱列表点「演示02」的“启动并打开”，启动和构建期间去看「案例03」的详情。演示02 启动完成时，界面自己切到了演示02 的终端页。测试人员接着点“删除沙箱…”，确认框的目标已经是演示02，及时取消才没删错。

## 原因

- 列表的“启动并打开”（`SandboxRow` 的 `enter`）等启动完成后，只要用户还在沙箱页（列表或任何一个沙箱的详情），就把详情切到这个沙箱的终端页，并自动开一个会话。启动可能要几分钟（首次构建镜像约 8 分钟），这期间在看别的沙箱的人会被带走。去了请求日志等其他页面的，看不到切换，但详情已经在后台换掉。
- 创建对话框的“创建并启动”也一样：启动完成后切回新沙箱的终端页并开会话。
- 删除确认框显示的名字本身没错，就是当前详情的沙箱；问题在于当前详情被换掉了。
- 复查又发现两处同类问题：
  - 在列表上开着对话框时启动完成，页面照样切换。对话框在列表和详情里各渲染一份，切换时会重建，勾选和填写的内容被重置：删除确认里勾的“保留 Agent 的配置和会话记录”变回不勾，再点删除就连配置一起删了；创建对话框里填的名称被清空。
  - 删除完成后用点“删除”那一刻的详情判断要不要回到列表。删除期间去看了别的沙箱的人会被踢回列表。

## 改动

- `frontend/src/main.js`：记下当前所在的页面和详情，通过 `currentView()` 让沙箱页在异步操作完成时查看。
- `frontend/src/js/sandboxes.js`：
  - **启动并打开**：启动完成时还停在沙箱列表，或者停在这个沙箱的终端页，才打开终端并开会话。打开了别的沙箱、这个沙箱的其他标签页或别的页面，就只提示“「名称」已启动”（5 秒后消失）。
  - **创建并启动**：启动完成时还停在新沙箱的终端页，才开会话；否则只提示。
  - 以上两种，开着任何对话框时都只提示，不切换。
  - **删除**：完成时按当前所在的详情判断，正在看被删的沙箱才回到列表。
  - 沙箱已经在运行时，“打开”“继续工作”不用等待，照旧直接打开。
- 没改的同类跳转见“范围与限制”。

## 实测

用 WKWebView（macOS 26.6.1，每次不留缓存）加载真实前端和模拟后端，模拟后端的启动固定等 2 秒。同一套步骤分别跑 main（3d1bb4c）和本分支：

| 场景 | main | 本分支 |
|---|---|---|
| A：列表点「演示02 启动并打开」，启动期间打开「案例03」详情，完成后点“删除沙箱…” | 切到演示02 的终端页并开了会话；删除确认框是「演示02」 | 停在案例03 的概览，提示“「演示02」已启动”，没开会话；删除确认框是「案例03」 |
| B：点「演示02 启动并打开」后一直停在列表 | 打开演示02 的终端并开会话 | 同左 |
| C：“创建并启动”，启动期间点“全部沙箱”回到列表 | 被带回新沙箱的终端页并开了会话 | 停在列表，提示“「新沙箱」已启动” |
| D：“创建并启动”后一直停在新沙箱的终端页 | 开会话 | 同左 |
| E：列表点“启动并打开”，启动期间切到“请求日志”页 | 停在请求日志，没有任何提示 | 停在请求日志，提示“「演示02」已启动” |
| K1：点「演示02 启动并打开」，启动期间在列表打开「案例03」的删除确认并勾“保留”，完成后点删除 | 切到演示02 终端；“保留”被重置为不勾，实际调用 `DeleteSandbox(案例03, false)` | 停在列表，只提示；“保留”仍勾着，调用 `DeleteSandbox(案例03, true)` |
| K2：同上，启动期间打开创建对话框并填好名称 | 名称被清空 | 名称保留 |
| L：在演示02 详情里删除（耗时 2 秒），删除期间去看案例03 | 删除完成后被踢回列表 | 停在案例03 |
| G：点「演示02 启动并打开」，启动期间打开演示02 自己的终端标签 | 开会话 | 开会话 |
| F：同上，但打开的是演示02 的概览 | 切到终端并开会话 | 留在概览，只提示 |

场景 A 在 main 上复现了报告里的现象。K1、K2、L、F、G 和启动失败、启动被停止、已运行沙箱直接打开、教程创建沙箱、恢复会话等场景用独立复查人的模拟后端跑，启动失败、被停止、已运行和恢复会话的行为与 main 相同。前端 `node --test` 28 项、`make check` 通过。

## 范围与限制

- 只在 WKWebView 加模拟后端里验证，没在打包好的应用里用真实沙箱试。
- 启动完成时如果用户正好回到了沙箱列表，仍然会打开终端，这是“启动并打开”本来的意思。
- 启动失败时的提示没有改动。
- **没改的同类问题**：
  - 教程进行中，教程沙箱上的操作（停止、重启以应用、更新智能体）结束时，教程会按当前步骤自动跳到教程沙箱的页面，正在看别的沙箱的人会被带走（复查实测）。改动会影响教程每一步的跳转，留到后续单独处理。
  - 提示条在页面顶部占位，出现和消失时下面的内容会上下移动约 80 像素。确认框仍显示当前沙箱的名字，误点的后果有限；可以改成浮层。
  - 对话框随列表和详情各渲染一份，切换时仍会重建；这次的做法是开着对话框时不切换，没有改渲染位置。
