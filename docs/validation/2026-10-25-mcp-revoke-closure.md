# MCP 权限撤销闭环验证

日期：2026-10-25

本次验证覆盖停止沙箱和运行中撤销 MCP 服务两条路径。撤销动作由运行时统一处理：清空 Gatekeeper 当前策略、删除可信连接器、清理宿主进程内的连接器令牌，然后停止 Agent 和门卫容器。

## 验证结果

- 沙箱停止前，Gatekeeper 被下发空策略；即使容器停止过程出现延迟，旧模型和 MCP 请求也不能继续获得已授权出口。
- 停止沙箱时删除连接器容器，避免数据库密码和连接器启动文件留在停止容器中。
- 连接器令牌按沙箱前缀清理，不会误删其他沙箱的运行期令牌；下次启动重新生成令牌并重新投递秘密。
- 运行中的沙箱通过 MCP 设置取消服务时，既有刷新逻辑仍会删除不再需要的连接器并重新下发 Gatekeeper 配置。
- 项目目录和 Agent home 不受撤销影响，便于用户继续工作。
