# 本机 AI 控制验证

提供桌面二进制 `--mcp` 与 `cagectl ai serve` 两个 stdio 入口；设置生成当前应用可执行文件的绝对路径和参数。无新常驻服务或网络监听。新控制实例只记录自己创建的沙箱，供应商列表返回最小字段；任务复用官方结构化 CLI 桥接，正文走 stdin，不作为宿主命令参数。

每会话 8 个沙箱、16 个任务、2 个并发；创建接口最多 100 次请求/100000 token，可调低；任务最长 600 秒。读任务结果有长度和工具数量上限；取消按独立进程标记清理容器内进程。退出停止自己的沙箱并保存用量，不删除项目。

补齐本地多进程协调：元数据更新使用同一文件锁，读取仍使用原子替换的完整 JSON 快照；沙箱生命周期按 ID 加锁，虚拟机启动/替换与停机使用共享/独占锁。文件名由摘要生成，并拒绝符号链接。

验证：

- 三个真正独立的 Go 测试进程同时对同一存储累计写入，共 60 次更新，结果为 60，无丢失。
- 同一 Manager 和两个独立 Manager 对同一沙箱互斥，两种等待者均按超时返回。作用域、任意项目路径拒绝、凭据不返回、额度边界、并发限制与取消回归通过。
- 实际构建的 cagectl 完成 stdio 初始化、发现 8 个工具、已有沙箱不可见和 EOF 正常退出。协议在初始化前拒绝工具调用。
- 两个一次性真实沙箱并发使用 DeepSeek 完成不同暗号任务，轮询得到正确结果；随后第三项任务进入实际 Bash 工具执行，取消后确认容器内该标记的进程为 0。正常退出后两沙箱停止，持久用量非零。全组 7.81 秒通过。
- 相关竞态、生产编译/vet、JS 语法通过；Chrome 合成界面验证连接配置和说明。
- 测试使用临时元数据及新建项目/容器，均已清理；用户原有供应商、绑定和沙箱没有变更。

真实验证命令：`AIOFCAGE_CONTROL_E2E=1 go test ./internal/service -run '^TestAgentControlEndToEnd$' -v`。该项会使用已配置 DeepSeek 供应商发送少量测试请求。
