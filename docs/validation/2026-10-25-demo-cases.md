# MCP 案例验证

新增内置合成业务连接器及三个案例。无需新 npm 包、无新增公网服务或持久凭据；复用可信连接器的镜像与门卫。凭据分支覆盖保存、读取、测试与删除，内置案例不访问钥匙串。参数限定数据集、文本筛选与分组字段，禁止任意命令、SQL、文件和 URL。

DeepSeek Harness 的固定官方包已包含 `dsh-mcp-client`。根据其随包 README 和配置示例生成插件 overlay，HTTP 仅携带占位符；filesystem 只传当前项目路径。会话模型 overlay 在其后生效，保留 MCP 配置。不是另装来源不明的 CLI。

验证结果：

- 数据统计与边界回归：campaign 4 单、实付 3000、退款 2000；重复扣款筛选 2 单。不存在工具/数据集、任意 URL、过大读取与错误分组均拒绝。stdio 初始化、列工具和取数通过。
- 相关 Go 竞态、JS 语法、vet 与生产编译通过；内置服务没有密钥字段，也不会删除不相关钥匙串条目。
- 三个独立真实沙箱均完成 MCP 初始化、列工具、读取各数据集、拒绝越权工具及 DELETE 关闭。拒绝返回 MCP JSON-RPC -32001，HTTP 200 是协议错误承载，不代表工具执行成功。
- 真实 DeepSeek 从新案例创建流程启动，使用原供应商的只读配置引用，不更改用户配置；实际 3 次 MCP 工具调用后生成 `report.md`，核对订单 ID、75% 退款订单比例与合成数据声明通过。整组 29.05 秒完成。
- Chrome 合成数据验证案例库、Agent/供应商选择、创建后进入详情、任务展示和复制入口；此项不冒充真实容器验证。
- 真实测试只使用本轮新建的项目和容器，均已清理；用户原沙箱未变更。

运行方式：`AIOFCAGE_DEMO_E2E=1 go test ./internal/service -run '^TestDemoCasesEndToEnd$' -v`。额外设置 `AIOFCAGE_DEMO_AGENT_E2E=1` 才会使用已配置 DeepSeek 供应商进行真实模型任务。

2026-10-25 原生验收中，DeepSeek 选择“高”思考强度完成退款案例，7 次工具活动后写出报告并正确续聊。模型指出任务引用了日期但订单数据没有日期字段；已为十条订单补齐 `order_date: 2026-10-20`，增加按日期读取的单元与真实 MCP 断言。重建连接器后，三案例握手、列工具、取数、越权拒绝和关闭再次通过；真实 DeepSeek 再生成报告、核对指标及记录 ID，通过，整组 40.03 秒。该修正不改变原金额与比例。
