# 终端新建菜单修复（2026-10-25）

## 原因与改动

在原生应用、空终端中复现菜单左侧被裁切：新建按钮靠左，而菜单使用 `right: 0` 对齐；菜单宽于按钮，向终端面板外伸出后被 `overflow: hidden` 裁掉。

菜单改为默认向右展开，打开时按实际终端面板边界计算位置、最大宽高；窗口和面板尺寸变化时重新定位。已有会话、按钮靠右时，同样把菜单限制在面板内。保留原生 details/summary 和按钮，不增加依赖。

补齐上下方向键、Home/End 导航及 Escape 关闭后归还焦点；点击外部、焦点离开和选择选项时关闭菜单。禁用的选项不参与键盘导航。

## 实测

- 1180px 原生窗口：空终端的四个选项完整；已有 Shell 会话时，靠右的菜单也完整可见。
- 900px 最小宽度原生窗口：空终端、已有 Shell 会话两种布局均没有左右裁切。
- 键盘方向键、End、Enter 成功打开 Shell；Escape 关闭菜单并把焦点归还“新建”。
- `GOCACHE=/tmp/aiofcage-go-cache make check app` 通过；正式应用已重新构建，严格签名验证通过。
- 现有前端 Node 测试共 10 项通过；新增和修改模块的语法、`git diff --check` 均通过。

测试使用独立应用副本及一次性沙箱 `uat-menu-20261025`，没有绑定供应商、调用模型或产生推理用量。测试沙箱元数据、容器、网络、home 卷、空项目目录和临时应用副本均已清理；原有两个沙箱及服务保留。

关闭测试应用时原应用也退出了，随后已重新打开正式应用，并在 `s9-db` 空终端再次确认四个菜单选项完整。原生 DeepSeek 的三个压缩聊天文件仍在；应用当前仅在内存中保存会话标签，重启后未恢复先前打开的标签。本轮没有修改这项历史恢复行为。
