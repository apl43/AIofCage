# 终端“新建”菜单鼠标点选修复

[验收记录索引](README.md)

## 问题

11-01 决赛前全量实测的问题 F02：在沙箱详情的“终端”页点“新建”，菜单能展开，再用鼠标点 Codex 或 Shell，菜单收起，不开新会话（Claude Code 走同一段代码，当时没有单独点）。同一轮测试里，Claude Code 在长任务沙箱里一次模型请求都没有（审计日志里 146 条模型请求都来自 Codex），推测也是这个原因。

## 原因

- macOS 的 WebKit 点按钮时不把焦点交给按钮，而是交给最近的可聚焦祖先。界面的 `<main id="main-content" tabindex="-1">` 可以聚焦，焦点就从“新建”移到了 `<main>`。复查时去掉 `<main>` 的 tabindex 再试，焦点直接丢失，菜单照样收起，所以问题不取决于 `<main>`。
- 菜单 `<details>` 的 focusout 处理是“焦点移到菜单外就收起”。`<main>` 在菜单外，所以鼠标一按下菜单就收起了；抬起时选项已经不在原处，click 落在下面的终端面板上。
- 这段 focusout 是 10-25 的菜单修复（2052279）加的。当时用方向键和 Enter 验证，键盘选择时焦点就在菜单里的按钮上，不受影响，所以没发现。内置浏览器（Chromium）点按钮会把焦点交给按钮本身，也看不出这个问题。

## 改动

- `frontend/src/js/sandbox-detail.js`：在菜单选项上按下鼠标时取消默认动作（`preventDefault`），焦点不移动，菜单保持展开，直到选项的 click 处理完。供应商表单和终端里的模型下拉，选项本来就是这样做的。
- `frontend/src/main.css`：禁用的选项（比如上一个会话正在打开时）不接收鼠标，按下由外层的选项区接住，菜单同样不收起。复查发现 WebKit 在禁用的按钮上不派发 mousedown，只靠上一条拦不住。
- focusout、点菜单外收起、方向键和 Escape 的逻辑都没改。

## 实测

用 WKWebView（macOS 26.6.1，WebKit 21624.4.5.11.5）加载真实前端 `frontend/src` 和模拟后端（只返回固定数据：一个运行中的沙箱，绑定 Codex），向窗口发真实的鼠标和键盘事件。同一套步骤分别跑 main（3d1bb4c）和本分支：

| 步骤 | main | 本分支 |
|---|---|---|
| 鼠标点“新建” | 菜单展开 | 菜单展开 |
| 鼠标点 Codex | 菜单收起，没有新会话，焦点停在 `<main>` | 开出 Codex 会话（`StartConversation` 收到 codex） |
| 再点“新建”，点 Shell | 没有新会话 | 开出 Shell 会话，共 2 个标签 |
| 打开菜单后点菜单外的“项目文件”按钮 | 收起 | 收起 |
| 焦点在“新建”上按 ↓ | 展开，焦点到 Codex | 同左 |
| 再按 Enter | 开出 Codex 会话 | 同左 |
| 按 ↓ 后按 Escape | 收起，焦点回到“新建” | 同左 |
| 按 ↓ 后按 Tab 离开 | 收起，焦点到下一个控件 | 同左 |
| 会话正在打开（选项禁用）时，再打开菜单并按在选项上 | 菜单收起 | 菜单保持展开，不开会话 |

- 事件追踪印证了原因：在 main 上点 Codex，依次是按钮上的 pointerdown、mousedown，然后“新建”的 focusout（relatedTarget 是 `MAIN`），菜单收起，最后 mouseup 和 click 落在终端面板上。
- 独立复查在真实 WebKit 里逐条复现了上表，另外确认：始终显示的滚动条，本分支上能按住拖动，菜单不收起（main 上一按就收起）。
- 前端 `node --test` 28 项通过，`make check` 通过。

## 范围与限制

- 本次没有在打包好的应用里用真实沙箱点一遍。WKWebView 和应用用的是同一个系统 WebKit、同一份前端代码，后端没有改动。彩排时请在“沙箱详情 → 终端 → 新建”里用鼠标点一次 Claude Code 确认。
- WKWebView 运行器和模拟后端是临时测试工具，没有放进仓库。
- 模型下拉也是“焦点离开就收起”：选项已经用同样办法保护，但列表的滚动条区域没有，按住滚动条列表就收起。这在终端模型下拉的 PR 里一并修。
