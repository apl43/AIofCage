# 产品目标、设计冻结与验收

> 设计草案 v1 · 2026-10-23。本文规定目标和通过条件，不代表功能已经实现。
> 议题原文见[比赛规则](competition-rules.md)，组件与执行机制见[架构设计](architecture.md)。

## 1. 产品要达到什么结果

用户把一个项目交给桌面应用，选择 Agent 和需要的服务，就能在受控环境里完成任务。用户在宿主应用中绑定模型和 MCP 账号；Agent 可以使用获准的能力，但拿不到这些账号的上游 API Key、密码、访问令牌和刷新令牌。用户能看懂授予了什么权限、为什么被拦截，以及怎样停止访问。

产品首先面向 macOS Apple Silicon 上使用编程 Agent 的个人和小团队。平台限制是团队的首发选择，需在介绍与演示中公开。题目没有定义“所有主流 MCP”的固定名单，下述清单是团队的最低验证基线，不能自行替代组织方的范围解释，更不能以有限样本证明全生态兼容。

| 目标 | 对用户的价值 | 达成证据 |
|---|---|---|
| 隔离项目、网络和上游凭据 | Agent 出错时限制影响范围 | 越界读取、直连、认证泄漏和跨会话测试；真实任务仍能完成 |
| 兼容题目列出的 Agent | 用户保留熟悉的工具 | Codex、Claude Code、dsh 各自的固定版本、任务结果和 MCP 调用记录 |
| 覆盖常见 MCP 认证与传输方式 | 不用把密码复制到沙箱 | HTTP 静态凭据、OAuth、stdio、数据库连接分别通过验收 |
| 普通用户可独立完成操作 | 无须理解 Docker、证书和 JSON 配置 | 首次安装至任务完成的操作观察与屏幕录像 |
| 权限可理解、可撤销，结果可追查 | 用户知道允许了什么 | 权限摘要、拒绝原因、撤销后测试和脱敏事件 |

可写工作区仍可能被修改或删除；获准工具仍可能返回敏感业务数据。保护上游凭据不能替代项目备份、数据分类和最小工具权限。

## 2. 需求到验收的对应

状态只使用“设计中 / 待验证 / 已验证 / 阻塞”。“已验证”必须附提交号、环境和证据；当前全部处于设计或待验证阶段，团队此前在其他沙箱的实验只能作为参考。

| 编号 | 来源与要求 | 设计承担者 | 必须通过的验收 | 当前状态 |
|---|---|---|---|---|
| R1 | 议题：核心是安全 | 专用 VM、Agent 容器、门卫 | 未挂载宿主哨兵不可读；直连 IPv4/IPv6、自建 socket、非授权 DNS、管理端口均不可绕过；合法请求可用 | 待验证 |
| R2 | 议题：主流 Agent | 启动配置与固定镜像 | §3 的三个 Agent 分别完成真实任务与 MCP 调用，不以显示版本或启动 shell 代替 | 待验证 |
| R3 | 议题：MCP 不填敏感信息 | Keychain、MCP 网关与可信连接器 | §4 四类服务跑通；沙箱环境、文件、进程参数和镜像层无上游秘密；过期、撤销、串用均关闭访问 | 设计中 |
| R4 | 议题：最终用户友好 | 桌面安装、连接向导、权限预设 | §5 全流程由非项目作者独立完成，不手改 Docker、CA 或 Agent/MCP JSON；失败时有可执行的中文下一步 | 设计中 |
| R5 | 团队安全承诺：权限与审计 | 门卫、MCP 网关、事件、应用 | 显式拒绝优先；MCP 写工具不可借 POST 放行；事件来源明确，日志缺口可见，导出无凭据 | 设计中 |
| R6 | 团队增强：额度保护（可延后） | 门卫额度执行器 | 若启用：并发请求不绕过请求数上限；重启恢复前关闭转发；估算费用和实际账单分开展示 | 待验证 |
| R7 | 交付规则：源码、运行说明、架构与分工、视频 | 团队提交与发布 | 从干净环境按说明重建；所有提交物可访问；真实作者与 PR 历史完整 | 待验证 |

R1—R4 直接对应议题。R5 是本产品用来兑现安全目标的具体方案；R6 是团队增强项。先完成题目基本能力，再做 AI 解说、审计 hash 链、高级策略编辑器和界面装饰。删减增强项不能掩盖基本能力缺口。

## 3. Agent 兼容基线

| 客户端 | 必须记录的环境 | 任务验收 | 当前证据与待解决项 |
|---|---|---|---|
| Codex | Linux/arm64 构建、镜像摘要、版本、模型提供方、认证与 CA 配置 | 在测试仓库修改文件并运行项目检查；调用已授权 MCP；撤销后调用失败 | 其他沙箱有团队实验；本项目环境需重测，不能把实验版本写成通用最低版本 |
| Claude Code | 同上，额外记录选用的 API Key 或账号登录链路 | 同上；流式响应、重试、子进程信任链可用 | 认证方式与可用模型待验证；占位符是否被接受需实测 |
| dsh | 确认议题所指产品、官方分发位置、Linux/arm64 产物、版本和授权条款 | 同上 | 产品身份与可用二进制尚待确认；不能拿其他同名程序替代 |

以上每个客户端需验证 HTTP MCP；本地仅支持 stdio 时使用无上游凭据的桥接器连接网关。四类 MCP 在产品层逐类验证，并记录每个客户端的实际组合结果；不要求虚构所有组合均已通过。最低基线是三款客户端均有真实任务及一次 MCP 成功证据，且产品覆盖四类 MCP；某客户端对某类服务仍不可用时必须公开。

若 dsh 无适用发行版或任一客户端无法在隔离边界内认证，该项为阻塞。选择受控转译或另一隔离后端必须先补设计、性能与安全验证；不允许静默改为宿主执行。只有组织方确认缩小范围，才修改对外合规结论。

每条证据至少记录：日期、操作系统与芯片、Colima/Docker/镜像/客户端版本、传输与认证方式、脱敏配置、复现步骤、成功和拒绝结果、对应提交号、验证人。当前不填推测版本，不勾选通过。

## 4. MCP 覆盖目标与凭据方案

### 4.1 四类最低基线

| 类别与代表 | 接入设计 | 正向验收 | 反向验收与限制 |
|---|---|---|---|
| HTTP 静态 Token：GitHub 官方远程 MCP | 可信网关持有固定上游 Token，Agent 连接会话绑定的内部 MCP 入口 | 初始化、列工具、读取专用测试仓库 | 未授权仓库和写工具被拒；沙箱无 GitHub Token；只读 Token 与网关限制同时生效 |
| HTTP OAuth：Notion 官方托管 MCP，作为候选 | 宿主浏览器授权，可信 OAuth 客户端与网关使用令牌 | 登录、初始化、查询测试页面、令牌到期后续用或重新登录 | state/PKCE 校验失败、授权取消、过期和撤销均关闭访问；不要求沙箱输入或保存上游令牌 |
| 无密钥本地 stdio：filesystem 参考服务 | 沙箱内运行固定版本；只允许项目内工具，必要时通过无密钥桥接器 | 列工具、读取项目测试文件 | 读取项目外哨兵和符号链接逃逸均失败；无宿主目录追加挂载 |
| 有密码的 stdio / 非 HTTP 后端：PostgreSQL 测试连接器 | 可信连接器在 Agent 外持有只读数据库凭据，网关代理其 MCP 能力 | 从隔离测试数据库查询固定测试表 | 无法写表、越库或读取其他连接器凭据；Agent 不获 DB 网络直连和密码 |

GitHub、Notion 是服务候选，filesystem 和数据库连接器的包、版本、摘要及许可证须在可行性验证时确定。PostgreSQL 不预设某个已废弃的参考包可直接用于产品。某个服务更换认证或停止开放接入时，先更新验证记录再调整基线，不悄悄换成模拟接口。

MCP HTTP 授权规范与 stdio 的凭据处理方式不同；把任意密码换成一个占位字符串不能自动兼容数据库协议。OAuth 也不能仅靠替换 `Authorization` 头完成首次授权、续期和撤销。HTTP 代理仍用于模型及一般网络；带凭据的 MCP 正常入口统一走协议网关，避免绕过工具权限。

### 4.2 最小可信接入层

门卫容器内增加 MCP 网关模块，复用现有配置版本、会话生命周期和脱敏事件，不另起一个宿主常驻服务。协议解析优先评估 MCP 官方 Go SDK；其仓库兼容说明包含客户端 OAuth 的实验性/部分支持限制，OAuth 不能按开箱可用估工，须固定 SDK 版本后实测，必要时单独采用成熟 OAuth 库。stdio 转接能力也须逐项核实。Docker MCP Gateway 作为可复用候选，只有同时满足网络隔离、凭据生命周期和事件接口要求时才替换模块。

```text
宿主应用 ── Keychain / 系统浏览器 OAuth / 固定连接器编排
    │ 鉴权管理接口 8899（宿主回环）
    ▼
可信门卫容器
    ├── HTTP 代理 8888：模型与一般网络策略、凭据注入
    └── MCP 网关 8890：会话认证、工具和参数策略、上游 HTTP/OAuth
          ▲                        │ 私有连接器网络
Agent 内网 ── 受限会话能力          ▼
    │                     可信连接器容器 ── 受限数据库后端
    └── 无密钥 stdio 桥接器          （只运行已批准服务）
```

- `8890` 只绑定 Agent 内部网络，既不是通用 URL 转发器，也不是管理入口。按会话、服务、工具和资源绑定至少 32 随机字节、最长 15 分钟的内部凭据；续期由宿主在会话仍获授权时下发。它是沙箱内的授权能力，必须脱敏，但不是上游账号凭据。MCP 的会话 ID 本身不能代替认证。
- 多会话使用独立 Agent 网络和独立门卫实例，不能把所有 Agent 放在共享内部网靠可猜的服务名隔离。`cage-internal` 是单会话示意；实际网络名加会话标识。
- 网关维护 Agent 连接与上游 MCP 会话的映射，支持所需的初始化、能力协商、请求、通知、取消与流式返回；未实现能力不对客户端宣告。限制报文大小、并发和超时，未知方法默认拒绝；`tools/list` 和执行检查使用同一权限集。
- 不默认透传 sampling、elicitation、roots 或服务端向客户端的文件/模型请求；逐项支持前保持关闭，不能绕过已有项目和模型权限。
- 工具授权以服务 + 工具名 + 类型化参数校验为基础。未知 schema 或不能约束资源范围的工具保持关闭；上游只读账户提供第二道限制。不能仅凭 `readOnlyHint` 或工具名含 `read` 就放行。
- 所有重定向、服务发现和授权服务器 URL 都需校验协议、目标、解析 IP 与端口，防止 SSRF 进入宿主、元数据地址或管理面；DNS 重解析与跨域重定向都重新检查。
- 带凭据的远程 MCP 端点不同时开放 Agent 直连 HTTP 注入路径。模型网络规则也不能附带放开同域 MCP 路径；不能跳过 MCP 工具权限去调用底层 API。

### 4.3 OAuth、秘密与撤销

1. 宿主应用是上游 OAuth 客户端，打开系统浏览器，使用精确注册的本地回调、随机 state、PKCE；校验授权服务器与回调归属。回调仅在授权窗口期监听回环，不能放进 Agent 网络。
2. 按服务元数据发现资源及授权服务器，携带正确的资源标识和 scope；禁止把给网关签发的内部 token 当作上游 access token 透传。上游令牌只发给它绑定的资源。
3. 客户端注册依服务支持选预注册、DCR 或客户端元数据文档，不假设所有服务都开放 DCR。若服务只接受公网元数据 URL、本地回调不受支持或需尚未获得的客户端注册，该服务标记阻塞，先解决注册条件。
4. 需持久化的密钥、访问令牌、刷新令牌和客户端秘密只进入 Keychain，非敏感元数据单独保存。宿主传输时短暂持有，门卫运行时内存持有；刷新令牌优先仅由宿主持有。每个授权串行刷新，轮换结果原子持久化，`invalid_grant` 停止刷新并要求重新登录，不能并发重试旧令牌。应用退出后，到上游 access token 或内部凭据任一到期即停止该服务，不无限延长。
5. 可信连接器只持有本服务所需的运行期凭据。由宿主经已认证的私有配置通道下发，不写镜像、命令参数、普通环境变量、Docker 元数据或磁盘卷；交付通道在验证关口必须证明可行。
6. 本地撤销先禁止新调用并注销内部 token、取消可取消的在途调用、清除绑定；再尝试上游撤销与 Keychain 删除。无法撤回已在上游完成的写操作；“本地断开”和“上游授权已撤销”分开展示。

### 4.4 可信连接器的边界

连接器是接触秘密的可信代码，不能接受 Agent 提供的 shell、镜像、`npx -y`、项目 MCP 配置或任意启动参数。用户只能从已审查目录选固定镜像摘要、固定程序与经过类型校验的参数。引入新连接器是单独的审查和验证动作。

宿主编排每个会话、每个服务的连接器容器。容器只与门卫共享独立的连接器网络，Agent 不接入；连接器提供需独立认证的内部 MCP 适配入口，内部再以 stdio 启动固定服务，不挂载 Docker socket。连接器无项目挂载、无其他服务秘密；如工具确需文件范围，另行声明最小挂载与测试。

首个数据库验收使用同一隔离网络内的测试数据库，不给连接器直接附加无限制外网。接真实外部数据库前，必须验证仅可访问固定后端地址和端口的出口控制；普通 HTTP 代理不能承担 PostgreSQL 协议的控制。缺少这层能力时，只能标注测试后端支持，不能宣称任意外部数据库已可用。

连接器与门卫共享 VM，因此 VM 高权限逃逸仍会突破秘密保护；连接器被攻破也可能泄露它自身的凭据。接入层减少 Agent 接触面，不保证上游服务、返回内容或连接器本身天然安全。

## 5. 普通用户的完整操作流程

| 步骤 | 用户做什么 | 产品必须处理什么 | 失败时必须提供什么 |
|---|---|---|---|
| 环境准备 | 打开应用，确认资源占用和必要安装 | 检查芯片、虚拟化、依赖、下载与专用实例；自动配置网络和容器 CA | 显示缺哪个条件、怎样重试或取消；安装失败不启动宽松环境 |
| 导入项目 | 选文件夹，确认副本位置和可写/只读 | 外部目录导入工作区，显示原件与副本关系，解析符号链接并限制共享 | 空间不足、路径不合规、导入失败的中文说明；不暗中扩大共享 |
| 绑定模型 | 填宿主密钥表单，选服务 | Keychain 保存，后端连通测试，生成占位配置 | 区分认证失败、模型不支持、证书/网络失败；不显示密钥原文 |
| 连接 MCP | 选服务、登录或填宿主密码表单 | 展示服务、账号、工具、资源与写权限摘要；自动生成无上游秘密的沙箱配置 | 取消授权、权限不足、服务不支持可退出/重试，不要求复制 token 到终端 |
| 启动任务 | 选 Agent，确认项目和权限，启动 | 完成全部就绪检查后才启动，显示运行状态和终端 | 启动失败收回临时能力；提供脱敏诊断和具体下一步 |
| 处理拒绝 | 看目标、原因、风险；决定后续授权 | 只有允许扩展的默认拒绝可变更；等待执行方确认版本后显示生效 | 告知原调用已结束，需要客户端重试；明确禁止项不可一键绕过 |
| 停止/撤销 | 停止会话或断开服务 | 撤销内部能力、关闭连接器、显示文件变化与遗留授权 | 说明停止失败、上游撤销失败或仍需外部处理的授权 |
| 清理 | 确认保留项目/审计/账号哪些内容 | 明确区分停止、删除沙箱、删除项目、删除 Keychain 凭据 | 删除前显示影响范围；不把清理容器理解为删除用户项目 |

首次体验验收：至少一位未参与实现的人在干净的受支持机器上按界面完成“安装—导入—绑定—启动—使用 MCP—拒绝—停止”，记录耗时、手动终端步骤和卡点。团队可预设可用性目标为十分钟内完成首次连接（下载与外部服务等待单独计时），这是待测目标，不能写成实测性能。

## 6. 先稳定设计，再开始功能编码

按最新开发安排，先建立可构建的桌面/门卫入口和模块接口骨架，当前状态见[模块说明](modules.md)。骨架不实现真实隔离、秘密存取或转发，也不构成设计冻结证据。下列技术关口仍须通过最小实验验证；每个实验保留脱敏复现记录，需要凭据时只使用独立测试账号。对应路线经验证并记录设计决策后，才启用真实安全能力。

| 关口 | 要解决的决定 | 通过条件 | 失败时怎么处理 |
|---|---|---|---|
| G0 需求与范围 | 什么算满足议题，哪些增强项可删 | R1—R7 有负责人、验收方式；主流基线与未覆盖范围明确，歧义有组织方答复或显式待确认 | 不能把未答复当默认同意；保留范围风险 |
| G1 隔离与管理 | 专用实例是否真的能执行边界 | 正常代理通；直连/管理访问绕过失败；共享、宿主监听、IPv6/DNS 检查有证据 | 调整网络/隔离方案并重测，不以打开外网绕过 |
| G2 Agent 与模型 | 三个 Agent 的发行和认证是否可用 | 固定产物、认证路线、CA、流式真实任务均可复现 | 无可行路线的客户端是核心阻塞；回到范围或架构决策 |
| G3 MCP 与 OAuth | SDK/网关能否承载四类基线 | HTTP/OAuth 完整会话、stdio 桥接、密码连接器、撤销与协议会话映射可复现 | 比较自有模块和现成网关；更换组件前补兼容/安全差异 |
| G4 秘密与权限 | 凭据如何送达，授权是否可绕过 | 可信工作进程配置通道不落盘；沙箱秘密扫描为零；工具越权、跨会话、SSRF、token 串用均拒绝 | 交付通道或策略未定不得开始相关正式模块 |
| G5 接口与工作量 | 多人能否按同一规格实现 | 管理、会话、MCP、审计字段和错误语义有样例；模块责任与预估工作量能放进剩余时间 | 删减增强项或承认核心目标暂不可达，不只改勾选状态 |

“设计稳定”指：目标与非目标一致；每个秘密的持有者和生命周期清楚；默认拒绝、撤销、故障恢复有定义；候选组件与关键技术风险有实验支持；验收能由另一位队友复现。**目前这些关口尚未通过，本文不能据此保证全部目标在比赛前可达成。**
