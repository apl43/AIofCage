> 历史记录：保留 2026-10-23 的产品方案、S0—S10 排期与当时分工。当前行为以[工作区规格](product-workspace.md)为准，构建与贡献见[开发指南](development.md)，实际结果见[验收记录](validation/README.md)。本文中的“已确认”“待实现”和时间点均指当时状态。

## 1. 产品形态：CC Switch + Docker Desktop

一个桌面应用，左边像 [CC Switch](https://github.com/farion1231/cc-switch) 一样管理 agent 的**供应商**，右边像 Docker Desktop 一样管理**沙箱**。

```text
供应商（按 agent 分类，真 key 只在钥匙串）
  Codex：      A（七牛 xapi）   B（另一家）
  Claude Code：C（某家 Anthropic 兼容接口）
  dsh：        D（DeepSeek）

沙箱（每个沙箱 = 一个 agent 容器 + 它自己的门卫）
  沙箱 1：装了 codex、claude   codex→A，claude→C
  沙箱 2：装了 codex           codex→A      ← 与沙箱 1 共用 A
  沙箱 3：装了 codex           codex→B      ← 使用另一个供应商
```

### 1.1 概念

| 概念 | 含义 | 关键字段 |
|---|---|---|
| 供应商 | 某类 agent 可用的一个模型服务 | 名称、所属 agent、接口地址、协议（OpenAI Responses / Chat、Anthropic Messages）、默认模型、key（只存钥匙串）、来源预设 |
| 沙箱 | 一个长期存在、可启停的隔离环境 | 名称、项目目录（位于 `~/CageWorkspace`）、已安装的 agent 列表、每个 agent 绑定的供应商、网络预设、状态、用量 |
| 绑定 | 某个沙箱里的某个 agent → 一个供应商 | 多个沙箱可以绑定同一个供应商 |

### 1.2 已确认的行为

1. **切换供应商在 agent 下次启动时生效**：应用改写沙箱内该 agent 的配置并更新门卫中的 key，正在运行的对话不切换（与 CC Switch 一致）。
2. **Claude Code 需要 Anthropic 格式的供应商**：七牛 xapi 只有 OpenAI 格式接口；DeepSeek、Kimi、GLM 等提供 Anthropic 兼容接口。
3. **额度上限按沙箱执行**：由各沙箱自己的门卫执行；供应商页面汇总显示所有沙箱的用量。跨沙箱共享上限放在后面。
4. **每个沙箱一个门卫**：门卫只持有这个沙箱绑定的供应商的 key，沙箱内只有占位符；占位符按“沙箱 + 供应商”生成。
5. **agent 的“下载”在专用 VM 内构建镜像完成**：按勾选的 agent 组合、固定版本构建镜像并缓存；沙箱运行时不联网安装，白名单只放行模型接口等必要目标。
6. **前端仍不需要 npm 构建**：在 `frontend/src/vendor/` 放入固定版本的 Preact + htm（ES 模块文件），用来写列表、表单和状态联动。

### 1.3 界面结构

侧边栏：**沙箱 / 供应商 / MCP / 日志 / 设置**。

- 沙箱：列表显示状态、已装 agent、绑定的供应商、请求数、token、拦截次数、CPU/内存；支持创建、启停、删除、打开终端、切换供应商。
- 供应商：按 Codex / Claude Code / dsh 分组；支持从预设添加、编辑、删除、连通性测试，显示有几个沙箱在用、累计用量。
- MCP、日志、设置的具体交互做到对应步骤时再细化，届时说明参考哪些应用。

## 2. 开发步骤

每一步一个分支、一个 PR，用 **merge commit** 合并，保留过程记录。PR 自测通过后由团队成员合并。时间为上海时区；功能冻结 10-26 00:00，07:00 前交付，09:00 官方截止。

| 步骤 | 时间 | 内容 | 完成标准 |
|---|---|---|---|
| S0 对齐文档 | 10-23 晚 | 本文；CLAUDE.md 写入产品形态与约定 | 团队成员在 PR 上同意 |
| S1 演示机复验 | 10-23 晚 | 在演示机复跑验证包，含真实 Codex 任务 | 记录进 `docs/validation/`；网络原因无法完成的项如实标阻塞 |
| S2 门卫产品化 | 10-23 晚 → 10-24 上午 | 把验证包中的门卫移入 `internal/gatekeeper`：多供应商占位符、`PUT /config`、SSE 事件流与补发、按供应商统计用量、额度；测试一并迁移 | 单元测试覆盖注入、拒绝矩阵、事件、用量 |
| S3 运行时产品化 | 10-24 上午，**13:00 检查点** | 用 Go 实现运行时：每个沙箱独立网络、门卫、agent 容器；agent 镜像构建；会话模型改为沙箱模型 | **Codex 在沙箱中经门卫完成真实任务**，沙箱内搜不到真 key |
| S4 供应商页 | 10-24 下午 | 页面结构调整；供应商增删改、钥匙串、预设、连通性测试 | 不碰命令行即可添加七牛供应商并测通 |
| S5 沙箱页 | 10-24 晚 | 创建向导（项目、agent、供应商）、启停、删除、打开终端、切换供应商 | 演示两个沙箱共用 A、一个用 A 一个用 B |
| S6 使用情况 | 10-25 上午 | 实时请求面板、每个沙箱的用量与资源占用、按供应商汇总、额度上限与 80% 告警、JSONL 审计 | 超额返回 429，界面出现告警 |
| S7 更多 agent 与 MCP | 10-25 下午 | Claude Code、dsh；MCP 先做 GitHub（门卫注入）与 filesystem（无密钥） | 三个 agent 各完成一次任务；MCP 调用成功，沙箱内无 token |
| S8 加分项 | 10-25 晚 | AI 安全解说；“模拟攻击”按钮（复用验证包探针） | 每次攻击在面板上标红并可由 AI 解释 |
| S9 补齐 MCP | 10-25 晚，至多 3 小时 | 数据库密码类 MCP（可信连接器持有密码）；时间允许再做 OAuth | 未完成的类别在文档中写明缺口 |
| S10 交付 | 10-26 00:00—07:00 | 冻结功能；README 运行说明、模块规格与真实分工、demo 视频；干净环境重建；密钥扫描 | 07:00 前全部合入 |

**检查点规则**：10-24 13:00 最小闭环必须跑通，否则当天下午集中修链路，不开始界面。时间不足时按此顺序删减：OAuth → 数据库 MCP → 内嵌终端（退回打开系统终端）→ 按供应商汇总额度。AI 解说与模拟攻击成本低，尽量保留。

## 4. 本机环境注意事项

- Docker Hub 在部分网络不可用：产品镜像使用 `public.ecr.aws/docker/library/...` 的官方镜像并固定摘要。
- `proxy.golang.org` 不可用时，构建使用 `GOPROXY=https://goproxy.cn,direct`。
- 所有 Docker 命令显式使用 `--context colima-aiofcage`，不修改用户默认 context。
