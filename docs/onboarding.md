# 新手教程

[返回 README](../README.md)

首次启动 App 时点击「开始设置」。之后可从左侧底部的「使用教程」继续或重新学习。

| 步骤 | 操作 |
| --- | --- |
| 检查环境 | 安装提示中缺少的依赖，再点「重新检测」。虚拟机尚未创建或未运行，可以继续。 |
| 配置供应商 | 选择智能体，添加供应商并填写模型和 API Key，也可直接选择已有配置。 |
| 创建沙箱 | 填写名称，新建空项目或选择已有项目；教程会预选智能体和供应商，也支持使用已有沙箱。 |
| 启动沙箱 | 点击「启动」并等待准备完成。失败后按提示修复，再次点击启动。 |
| 开始对话 | 打开智能体，填写自己的消息或点击「填入示例」，再手动发送。收到完整回复后完成教程。 |

消息会产生模型用量。可以选择「稍后体验」，此时结果显示“配置完成，尚未验证对话”。供应商的连接测试只检查接口可达性与返回状态，不能替代实际对话验证。

「退出教程」保存当前进度；直接关闭 App 后再次打开，会恢复进行中的教程。重新学习保留供应商、沙箱和项目。重新进入时会检查所选配置是否仍然存在、密钥是否可用，以及沙箱是否已经运行。

如果打开 App 时缺少运行依赖，安装后重新检测会提示退出并重新打开 App，以加载新的运行环境。升级前已经使用过 App 的用户，可主动点击教程入口。

## 实现与验证

- 教程复用供应商表单、沙箱创建与启动、智能体会话，执行结果来自这些现有操作。
- `frontend/src/js/onboarding.js` 管理入口、界面提示和进度写入；`onboarding-state.js` 校验实际配置及完成条件。
- `internal/service/onboarding.go` 通过本地应用设置保存版本、步骤、智能体和资源 ID；不保存 API Key、表单草稿或会话正文。
- 进度写入失败会显示错误并保留当前步骤；读取失败不会被当成首次启动。再次学习不会自动创建资源、发送消息或覆盖草稿。
- 会话必须属于所选沙箱、智能体和供应商，并且收到无错误的完整文本回复，才标记体验完成。空回复、仅思考、出错和停止均不算完成。

检查命令：

```bash
make check
make test
# Node.js 20.19+；仓库前端使用 ES modules。
node --experimental-default-type=module --test frontend/tests/*.test.js frontend/tests/*.test.mjs
```

自动测试覆盖首次启动与旧配置识别、进度保存与读取错误、资源删除或绑定变化、虚拟机初始状态、对话完成条件和草稿保护。

界面验收使用真实前端与模拟后端，覆盖首次进入、添加供应商、连接测试结果、创建和绑定、启动失败重试、重开恢复、重新学习、跳过试用、成功回复，以及保存失败后退出。也检查了 900 × 640 的最小窗口布局。本次未执行真实镜像下载、钥匙串授权和付费模型请求。
